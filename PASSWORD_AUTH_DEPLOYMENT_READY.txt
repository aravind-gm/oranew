✨ NEW ENDPOINTS (10 Total)

PUBLIC ENDPOINTS:
────────────────
POST /api/auth/register
  - Register new user with email + password
  - Response: { token, user }

POST /api/auth/login
  - Login with email + password
  - Response: { token, user }

POST /api/auth/admin-login
  - Admin-only login
  - Response: { token, user } (only for ADMIN role)

POST /api/auth/forgot-password
  - Request password reset
  - Sends email with reset link
  - Response: success message

POST /api/auth/reset-password
  - Complete password reset
  - Requires token from email
  - Response: success message

PROTECTED ENDPOINTS (Require JWT Token):
──────────────────────────────────────────
GET /api/auth/me
  - Get current user profile

PUT /api/auth/profile
  - Update user information (name, phone)

PUT /api/auth/change-password
  - Change password for authenticated user
  - Requires current password verification

DELETE /api/auth/account
  - Delete user account
  - Requires password verification

⚠️  IMPORTANT NOTES

1. DATABASE MIGRATION REQUIRED
   - Must run PASSWORD_AUTH_MIGRATION.sql before deploying backend
   - This creates the password_resets table and updates schema
   - Migration is backward-compatible and safe

2. EXISTING USERS
   - Users without passwords will have temporary invalid hash
   - They must use "Forgot Password" to set their password
   - Consider sending email notification to existing users

3. HTTPS REQUIRED
   - Password authentication requires HTTPS in production
   - Never send passwords over unencrypted connections
   - Configure SSL/TLS on your domain

4. EMAIL SERVICE
   - Forgot password feature requires working email service
   - Ensure SMTP is configured
   - Test email delivery before going live

5. ENVIRONMENT VARIABLES
   - JWT_SECRET must be set (for token generation)
   - FRONTEND_URL must be correct (for reset links)
   - Database URL must be accessible
